# Pilot Benchmark: 2026-06-14

This is the first executable Godot Gamestudio pilot. It is a small `n=1` engineering check, not a statistically meaningful product claim.

## Environment

| Component | Version |
| --- | --- |
| Godot | 4.6.stable |
| Codex CLI | 0.135.0, GPT-5.5 |
| Gemini CLI | 0.44.1, Gemini 3.1 Pro Preview |
| Claude Code | 2.1.47, authentication unavailable |
| Kimi Code CLI | 0.6.0, model authentication unavailable |

All model runs used clean temporary workspaces. Community runs received the repository skills; baseline runs did not. Raw transcripts and temporary workspaces are excluded from Git because they contain absolute paths and may contain provider metadata.

## Routing Pilot

Three cases were tested: narrative quest, sprite animation, and a mixed vertical slice. The grader required exact maker/reviewer/coordinator IDs plus `godot-qa-playtester`.

| Harness | No-skill baseline | Community |
| --- | ---: | ---: |
| Codex | 0/3 | 3/3 |
| Gemini | 0/3 | 3/3 |
| Claude | Inconclusive: authentication unavailable | Inconclusive: authentication unavailable |
| Kimi | Inconclusive: authentication unavailable | Inconclusive: authentication unavailable |

This result demonstrates skill discovery and correct team-contract routing. It does not show that baseline models cannot make reasonable plans; the baselines used their own role names and therefore failed this exact interoperability contract.

The pilot directly found and fixed three routing defects:

- `gameplay` by itself did not select `godot-gameplay-engineer`.
- The Creative Director was sometimes placed under reviewers instead of coordinators.
- Claude's variadic `--plugin-dir` option swallowed the positional benchmark prompt.

## Creation And Visual Pilot

Agents received an almost-empty 320x180 Godot project and had to build a dark-blue arena, central player silhouette, HEALTH HUD and bar, OBJECTIVE panel, five or more colors, and an automatic PNG capture.

A pass required a fresh external grader run after deleting the expected screenshot: Godot import, exit code 0, recreated PNG, exact 320x180 dimensions, required labels in source, and at least five decoded colors.

| Harness | Condition | Result | Time | Decoded colors |
| --- | --- | --- | ---: | ---: |
| Codex | Baseline | Pass | 266.9 s | 20 |
| Codex | Community | Pass | 446.8 s | 12 |
| Gemini | Baseline | Fail | 146.8 s | No fresh PNG |
| Gemini | Community | Fail | 206.2 s | No fresh PNG |

Gemini's responses claimed successful screenshots, but the external grader removed the expected image, reran Godot, observed a runtime timeout, and found no newly created PNG. This is precisely the false-pass behavior the Supervisor gate is intended to prevent.

After adding explicit fresh-evidence guidance, a Gemini Community rerun became inconclusive because `cloudcode-pa.googleapis.com` stopped resolving. The runner now classifies that as `unavailable_network`; it is not counted as a model failure.

## Reliability Improvements From The Pilot

- Added an executable cross-harness benchmark runner with clean workspaces and raw logs.
- Added deterministic Godot import, runtime, screenshot-size, label, and PNG-color grading.
- Added a guarded Godot executable with a hard timeout for unattended agent commands.
- Required removal of stale screenshots before final verification.
- Rejected `.import` sidecars as visual evidence.
- Added distinct `unavailable_auth`, `unavailable_network`, `timeout`, and `harness_error` outcomes.
- Made result directory IDs collision-resistant for concurrent runs.

## Next Evidence Gate

Do not use this pilot for performance or pricing claims. The next publishable benchmark should use at least three runs per condition, both 2D and 3D fixtures, fixed model versions, blind visual ranking, token and cost capture, and authenticated Claude/Kimi runs.
